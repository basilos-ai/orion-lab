# 简体中文与英文界面

Orion Lab 的对话、资源监控、项目管理、模型菜单、隐私说明、快速体验及执行详情使用同一套中英文语言资源。在“外观与使用说明”的“界面设置 → 界面语言”中选择“中文 / English”，即时生效；对话页可从左下角设置或顶部“对话操作”菜单打开，资源监控可从顶部外观入口或左下角设置打开。切换语言保留当前会话、未发送草稿、附件、模型和调用范围。

语言优先级为 URL 中有效的 `lang` 参数、浏览器已保存偏好、浏览器语言。支持 `zh-CN` 与 `en-US`，中文浏览器使用简体中文，其余浏览器默认英文。示例：`/chat.html?lang=en-US`、`/?lang=zh-CN#resources`。原有 `theme`、`conversation` 和页面片段保持原义。

浏览器以 `orion-locale-v1` 保存语言，不包含问题正文。相同源的标签页通过 storage 事件同步语言并更新 URL；对话与资源监控通常位于不同端口，通过页面跳转链接的 `lang` 参数传递语言。每个源分别保存自己的偏好。

## 实现与扩展

- `apps/console/src/lib/locale.ts` 管理有效语言、持久化、URL 与标签页同步。
- `use-locale.ts` 通过 React 的外部状态订阅触发更新，避免重新挂载页面或重建聊天状态。
- `i18n.ts` 提供 `t()`、应用状态文案转换、延迟读取的模型标签和错误展示。
- `messages.ts` 保存中文消息 ID 到英文文案的映射。中文 ID 兼容历史状态字符串；业务代码、模型 ID、API 及存储字段不随语言改变。
- 模块级文案在访问时计算，防止首次加载的语言被固定。日期和数值按当前语言格式化，设备时间仍使用原有时区。

新增应用文案使用 `t('中文消息')`；动态值使用 `t('移除文件 {0}', [filename])`，不拼接翻译后的句子。英文可调整占位符顺序，但不得增加或删除占位符。插值原样保留，避免修改文件名与用户内容。同时补充 `messages.ts`。

服务端返回的现有错误、选模原因和遥测提示在前端展示层转换，包括已经保存的历史错误。未识别错误显示当前语言的通用提示及可用诊断代码；未知诊断说明显示当前语言的缺少译文提示。接口响应、护栏判定、原始事件、审批绑定和服务日志保持原有格式。

## 内容边界

语言切换适用于应用自己提供的界面与提示。用户输入、已生成的模型回答、项目名称与说明、文件路径、正文、代码、差异和工具返回的文件内容保留原文。切换语言不额外调用模型或翻译服务。新插入的任务示例使用当前语言；示例进入输入框后作为普通草稿保留。

表单校验提示使用当前界面语言。浏览器自身的文件选择器、权限对话框、刷新前离开确认等由浏览器决定语言；应用无法重写这些浏览器原生提示。外链的 AI Gateway 等独立产品由其自身的语言设置管理。

普通聊天仍使用既有系统提示和请求格式，界面语言不改变回答模型的输出语言策略；可以在提问中指定回答语言。

## 验证

`npm test` 包含语言优先级、有效值校验、偏好订阅、动态标签、保存提示再展示、错误回退、用户标题保留、占位符一致性及所有字面量 `t()` 调用的英文资源完整性检查。

运行原有 `npm run typecheck`、`npm test`、Python 单测、`npm run check:source` 和 `npm run build`。浏览器单独检查两种语言、亮暗主题、1440 / 390 / 320 像素宽度、弹窗、草稿与附件保留、错误与拦截、资源状态、标签页同步、导出、键盘操作及无障碍。原始接口测试使用稳定代码，避免根据语言文案判断业务结果。
