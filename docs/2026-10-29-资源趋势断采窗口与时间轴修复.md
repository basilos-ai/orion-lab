# 资源趋势断采窗口与时间轴修复

日期：2026-10-29。用户截图显示 CPU 和内存趋势在左右两端聚集，中间留有很长空档，小趋势也有明显断段。

根因：前端没有跨请求合并历史，原图表直接展示接口返回的整个 history。原实现用空值打断跨越采样间隙的折线，但数字时间轴仍取全部历史的最早和最晚时间；中断前与恢复后的片段因此占据两端，中间空档压缩可读区域。原自适应纵轴也会纳入已过时片段的峰值。实时接口检查时采样已连续，本轮用隔离夹具明确重现中断场景，没有保存设备原始指标或用户截图。

适配：新增 resourceHistoryWindow，默认只取最近连续的一段，最多保留 60 个真实记录。沿用原有 3.5 秒连续性判定，并将阈值供窗口、趋势检查及曲线生成共同使用；时间无效、重复或回退同样形成边界。仅依据设备采样时间，不依赖浏览器当前时间，不排序、不插值、不补点，不过滤数值为 0 或为 null 的真实记录。原输入数组不变。

大小图统一使用此时间窗口：小图再截取最近 20 个记录；大图按当前连续段计算时间轴、纵轴和采样数。恢复后仅有一个点时等待连续采样，不能用旧片段让图表误判为已有趋势。发生时间中断时卡片说明当前只显示最近连续采样；当接口旧片段被后续连续数据替换后，提示自然消失。数值缺失仍在原位置断线，0、缺失、加载、失败和页面暂停的处理保持。

此决定更新前期“大图展示全部接口历史”的默认展示方式。原始 envelope.history 和快照导出未变，较早片段仍在当次接口提供的快照中，未承诺永久历史存储或额外后台留存。原代理、导航、其他页面与卡片密度保持。

验证：资源专项 35/35，包括桌面 / 手机、明暗主题、中断后窗口与小图计数、时间轴只落在当前片段、曲线使用可用宽度、旧峰值不压平新数据、恢复一个点的等待状态、连续采样恢复与原始 60 点快照导出；既有菜单、硬件、模型进程和概览密度用例均通过。报告及夹具截图：.harness/runs/resource-history-gap-20261029/browser/。
