# Resource monitoring contract

`GET /api/resources` is a same-origin, read-only endpoint served by the dashboard on O6N. Browser clients never receive SSH credentials, model API keys, raw process arguments or device serial numbers.

The response contains `status` (`warming`, `live`, `stale`), `sample`, `history`, `age_seconds`, `error`, `sample_interval`, `smi_interval` and `idle_seconds`. `sample` is null until the first valid sample. History has at most 60 points: timestamp, CPU percentage, available RAM bytes and maximum system-probe temperature. Missing measurements use null, never an invented zero.

`sample` holds host/kernel/time, aggregate/per-core CPU utilization, cpufreq values in kHz, memory/swap/root-filesystem byte counts, root-device read/write and physical-interface receive/transmit bytes per second, ACPI thermal probe readings, load average, uptime, llama-server process metadata and RSS totals, Docker cgroup memory, and accelerator records. The shared types in `apps/console/src/features/resources/resource-state.ts` describe the browser view.

Host RAM and Houmo card DDR are separate. Process RSS is a sum, not unique physical memory. Docker memory includes cache. Root-filesystem available space excludes reserved blocks. CPU utilization excludes iowait. Physical network traffic excludes Docker bridges/veth and loopback. CPU process percentage is normalized across the host cores.

Houmo records carry `power_state` (`active`, `suspended`, `resuming`, `suspending`, `unknown`), `smi_mode: "manual"`, `smi_ok`, `smi_age`, `smi_sample_at`, `smi_interval: 0`, `smi_valid_for` and a safe error message. Zero interval means there is no automatic card sampling. `smi_ok` only indicates a recent successful reading while active; it does not turn a manual snapshot into a live feed. Last successful numeric readings remain timestamped and labelled historical, even when old or the card becomes active again. The page does not present snapshots as current utilization, temperature, power or frequency. Without a successful manual read, values are N/A and the page invites the user to read once. A disconnected/paused host must not retain a current sleep badge. IPU utilization is percent; DDR counts are binary bytes converted from the SDK's MiB-valued MB labels; temperatures are Celsius, frequency MHz, board power watts. GPU utilization/VRAM and NPU utilization remain N/A where the kernel exposes no interface.

The device shares one host sampler across visitors, running every second. There is no SMI background worker, timer or automatic retry. Host collection only reads cached card snapshots and kernel-cached device identity/runtime power state; it never invokes SMI or reads live PCIe link configuration. Link information is captured with the manual snapshot. Waking the card for an actual inference does not trigger a telemetry query. Host sampling pauses after 15 seconds without resource requests. No governor, frequency, autosuspend setting, model/service control or hardware reset is changed.

`POST /api/resources/card-sample` accepts exactly `{ "bdf": "<detected PCIe address>" }` as JSON. This is the only telemetry acquisition path: it runs one `hm_smi -a -d <device_id>` query (4-second timeout), intentionally allowing that card to wake, then publishes a timestamped snapshot (`smi_manual: true`) and returns a resource envelope. Device ID comes from that PCIe device's IPU sysfs node. The page explains the brief wakeup and retains all readings as historical, including power/frequency after the device sleeps. A lock serializes concurrent manual requests; there is no automatic follow-up. The per-card 10-second cooldown rejects duplicate requests (409). Errors return 400/403/404/409/502 and are never automatically retried. Foreign browser origins are rejected. No raw commands or arbitrary paths are accepted.

The browser polls after each request completes and aborts requests on hide, pause or route unmount. GET request timeout is 4.5 seconds; a deliberate single read has a 6.5-second client timeout and updates the snapshot immediately. Retained data are labelled stale on errors or excessive age; expected page cadence (1/2/5 seconds) is accounted for. SMI age includes elapsed browser time, so an old card sample cannot retain a fresh badge during disconnection. Trend paths break over missing readings or idle gaps.

A portable reference adapter and its unit tests are included in `services/dashboard/`; the existing production process is preserved during this migration. It derives the probe logic from the existing Windows monitor's `RemoteProbe.py` v1.1. The frontend is independently buildable and has no Python runtime dependency.
