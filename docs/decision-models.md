# 独立分类模型对比

当前线上决策已可选Laya、后摩Qwen3.5-2B／4B，GLiNER保持独立实验。
后续经用户批准，4B另进入普通Ask轻量回答池，2B和MiniCPM-V手动可选；
分类实验本身仍不等于回答或Agent资格。最新边界见[answer-models.md](answer-models.md)。

## GLiNER 中文澄清独立实验

`#gliner-clarification` 读取单独的 `assets/gliner-clarification-experiment.json`，不覆盖历史分类对比文件。三分类映射保持 A/B/C，但候选内部采用有含义的英文标签、简短英文描述与中文已标注对照例。通过 SDK `ClassificationSchema.single(..., examples=...)` 编入真实 schema；只提供说明文字不代表模型实际收到了示例，应保存编译结果并核对。

开发集先比较原ABC、语义英文无示例、6例、9例；预先定义选择规则，再锁定候选。中文明确任务作为澄清负例，缺少必要目标或指代的任务作为正例。冻结集不参与配置选择，测试后不改标签。合成中文新集与已见旧题分别报告，需披露主题分组、标注来源、未独立人工复核的限制；重复请求不能增加独立样本数。

重点同时报告澄清召回、精确率、明确请求误澄清率、Macro F1与混淆矩阵。无预测澄清时精确率保持缺失。不要用提高C占比代替准确率提升，也不把澄清直接解释为云端调用。CPU8核FP32、单并发、离线权重，亲和性在导入torch前设置。完整schema和输入不截断编码的长度，应与实际推理长度逐条比对，样例增加的token和延迟另行记录。

原版与候选在同一独立进程中随机交错请求，共享权重和tokenizer缓存，无判决结果缓存。RSS为共享实验进程按请求分组的统计，不能代表独立服务的内存节省；HWM含加载。启动、预热及独立token核验不计入HTTP延迟，分类器自身预处理计入。严格不改线上GLiNER、Laya与Auto；不通过门槛也保留全部结果。

## 后摩生成模型扩展

Qwen3.5的小模型可以使用厂商编译的单芯片双核HiModel GGUF，经HLIELLama在LQ50上运行。普通CPU GGUF不能直接视为后摩模型。驱动、固件、运行库及模型编译版本应独立记录，下载后核对厂商长度、MD5及OSS CRC64，另存SHA256固定实际文件。

沿用冻结中文题集、分类说明、JSON Schema、关闭思考、temperature=0、24输出token和单并发。先确认运行库的约束JSON与缓存隔离机制可用，再开始正式测试；每次核对返回cache_n=0。厂商运行库若在显式slot擦除后出现checkpoint状态错误，可使用cache_prompt=false，并核对零前缀复用；不以重试或纠正隐藏协议失败。预热、选项逆序和自由JSON探测另计，不混入正式准确率，不按结果更改提示或题目。

后摩与CPU属于不同量化及后端的部署方案对照。分别展示主机RSS与整卡内存占用；卡内存包括运行时，不用低RSS证明总内存低。CPU卡内存显示不适用，后摩未测得显示缺失，真实零值保持为零。采样峰值不等于连续硬件峰值。

单卡实验使用临时回环服务，先取得既有benchmark锁并确认无用户任务，再暂时停止占卡回答模型。测试结束或正常中断时恢复原模型并验健康，释放锁。只测试文本时不加载投影器，不将结果当作图片识别成绩。实验不接入Auto，不改变Laya门限、仅本地限制、任务锁模或工具审批。

## 生成模型扩展

对比页兼容 MiniCPM5-1B、MiniCPM5-2B 和 MiniCPM-V 4.7 1B 等生成模型。复用冻结中文分类说明，Q4_K_M、8线程、4096上下文、关闭思考、temperature=0、24输出token；通过 JSON Schema 限定 `{choice: A|B|C}`。约束格式与语义分类分开核验，不把可解析JSON当作分类正确。

正式测试每次擦除独立 llama.cpp 服务的KV，并核对返回的 `cache_n=0`，包含完整提示预填和输出。生成模型无已校准分类概率，因此门限分数为缺失，不伪造概率或套用 Laya 门限。分类器FP32与生成模型Q4的资源比较属于实际部署配置对照，不能解释为同精度架构对照。

MiniCPM-V 可以加载F16视觉投影器后测纯文本请求，但此结果不代表视觉准确率、图片编码延迟或视觉峰值。模型按批次单独加载，避免同时竞争CPU；不因实验模型名称、分数或健康状态自动接入Auto。既有分类器结果归档单独保留，新增结果另行注入。

页面支持任意模型标签、模型／题集记录筛选、空结果、分页、原生分类与生成JSON配置，并兼容上一版两分类器数据。公开示例仍为空，模型、测量和部署证据保持私有。

GLiNER2.5-multi-Decide 是可选的实验分类服务，代码位于 `services/decision-models/gliner_cpu.py`。它不接入当前 Auto，不修改 Laya 提示、门限、任务锁定、云端授权或工具策略。现有 Agent 仍使用 Laya 在本地 9B 与已授权云端之间判断。

## 服务与依赖

GLiNER 代码、权重来自 [Fastino 模型仓库](https://huggingface.co/fastino/GLiNER2.5-multi-Decide)，本次固定 revision `e173bca1f0c4217d7a55b3b0c705d5ece8a0218d`。模型约 287M，FP32 权重约 1.15GB，权重 SHA256 为 `9efe0f88c99f2aa794452e9559dc60e98d60d9fa2bf1b60cf2710411b6da5b4e`。下载后应校验完整性。权重遵循其 Apache-2.0 许可，不随本项目 MIT 源码分发。

经过 ARM64 CPU 实际验证的独立 Python 环境：torch `2.6.0+cpu`、transformers `4.57.6`、gliner2 `2.1.0`、peft `0.17.1`、sentencepiece `0.2.1`、protobuf `6.33.0`、numpy `2.2.6`。禁止覆盖线上 Laya 的虚拟环境。模型及 tokenizer 预先下载到私有目录，运行时设置 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`，不加载仓库远程 Python 代码。

默认只监听 `127.0.0.1:17786`，健康接口 `/api/health`，分类接口 `/v1/classify`。请求包含 `state` 和 `questions.route`，其中 `type=choice`、`instructions`、`criteria={A,B,C}`。分类描述由调用者提供；服务不执行工具、不转发模型、不自动校准概率。只支持单并发，拒绝浏览器 Origin、超限或无效输入。

部署模板位于 `deploy/o6n/gliner25-multi-decide.service`，先把分类服务复制到私有运行目录的 `app.py`，安装独立环境、核对模型 manifest 后再安装 user unit。模板按 O6N 的 A720 核编号设置 affinity，其他设备需先核对 CPU 拓扑。若首次安装，应先准备适合平台的 CPU torch wheel；不要以安装 CUDA 包代替已经验证的 CPU 运行环境。

## 实验方法

新题 A/B/C 各 30 道，每模型重复两次；另有 40 道既有选模偏好回归。正式请求总数 440，6 次预热、24 次选项逆序测试另计。问题和预设标签在测试前冻结，保留全部失败，不按成绩改题。两模型使用同一份中文分类说明和 A/B/C 顺序、FP32、8 个 A720 核、交替单请求，无结果缓存。

线上 Laya 当时已有 Swap，RSS 直接比较会产生偏差，因此以同权重、同依赖的临时 Laya 实例测量。三条合成请求的结果与生产实例逐字段一致，测试后临时实例已停止，生产 Laya 未重启。

分别记录原始三分类、A→9B／B,C→云端的偏好符合率，以及相同 0.40/0.10 门限下的敏感性对照。两种模型的概率均未校准，共用门限不代表同等置信度。测试不调用回答模型，因此这些指标不等于最终回答质量、能力路由的最优率或实际云端调用比例。

测量回环 HTTP P50/P95、服务端推理时间、进程 RSS 中位数、100ms 请求采样峰值、含加载的 HWM 与 Swap。重复请求不算新的独立题目。短题不能验证长上下文；GLiNER API 的 `max_len=512` 不应误称为独立截断检测已通过。

## 看板与公开边界

React 看板 `#decision-routing` 从构建输入 `assets/decision-comparison.json` 读取结果，展示分组、分类别、延迟、内存、全部逐次记录及错误筛选。示例只保留空 schema；真实输入、测量、权重、下载及部署证据留在仓库外。

现成模型不能仅凭整体分类分数替换 Auto；还应验证需求不明确类别、误留本地、实际任务效果及资源开销。部署者本轮保留原 Auto，完整成绩通过私有构建输入展示，不随源码分发。后续应在未使用过的真实任务上验证类别、阈值校准和最终任务效果，再讨论灰度。

启动、停止、日志及静态回滚见 [operations.md](operations.md)。正式成绩应以部署者私有冻结集及看板为准，不能把官方英文分数当作本机中文实测。
