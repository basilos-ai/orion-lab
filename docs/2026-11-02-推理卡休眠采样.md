# 推理卡仅手动遥测与休眠

主机每秒自动采样不变。推理卡没有后台遥测线程、定时查询或自动重试，只有点击“读取一次”才获取卡载数值。

| 操作与设备状态 | 采样行为 | 页面显示 |
| --- | --- | --- |
| 未点击，设备休眠 | 只读取内核电源状态，不运行 SMI | 设备休眠；暂无快照或上次手动快照 |
| 未点击，设备被实际推理唤醒 | 仍不运行 SMI | 原快照及原采样时间保持不变 |
| 点击“读取一次” | 只查询指定卡一次，可能短暂唤醒 | 更新带时间的手动快照 |
| 读取失败 | 不自动重试 | 显示错误，等待用户手动重试 |

主机线程每秒读取内核缓存的设备身份和运行时电源状态，不读取实时 PCIe 链路配置，也不调用 SMI。卡型号、固件、链路和各项数值来自手动读取的缓存。手动查询使用该 PCIe 节点下 IPU `device_id` 指定 `hm_smi -a -d`，避免查询其他卡。多个访客共享同一主机采样器与手动快照缓存。

休眠历史值保留原时间，不能作为当前温度或功耗使用。服务重启后尚无成功遥测时显示“尚无设备唤醒时的采样”和 N/A，不为补齐页面主动唤醒设备。主机失联或页面暂停后，不将旧电源状态继续标为当前休眠。

该方案不修改 DVFS、频率上限、自动休眠延迟或模型服务。实际推理引起的唤醒由原驱动处理，不触发监控采样。快照只反映手动点击时的状态，不能据旧负载或旧温度推断当前运行状态。

## 手动读取一次

加速卡区域提供“读取一次”。它会短暂唤醒指定卡并查询一次，完成后显示带采样时间的手动快照。即使随后恢复休眠，快照内的负载、内存、温度、功耗、频率仍以“上次”标识保留，不能作为当前休眠功耗使用。按钮说明该唤醒行为，读取中和短暂冷却期间禁用重复点击，失败显示提示并等待用户手动重试。

手动请求共用互斥锁，每卡限制 10 秒内不重复查询。完成一次读取后没有自动补采样；即使卡继续运行或再次唤醒，也必须再次点击才更新数值。读取接口仅接受已检测设备的 PCIe 地址，不接受工具参数、主机路径或任意命令，不修改调频或电源配置。

## 验证

运行项目类型检查、JavaScript 单测、源码边界检查和构建；在 Linux 执行 `python3 -m unittest -v test_resource_probe`。单测覆盖主机只启动一个线程、任何电源状态均不自动查询、只有显式请求更新快照、多卡定向读取、重复请求、失败不重试和历史时间语义。界面验证桌面/手机、明暗主题和长期保留的手动快照。

部署后保持页面可见、API 持续请求，先运行一次有界本地短推理，验证运行和休眠均不生成卡载快照；再点击一次，验证仅生成一个采样时间戳、返回休眠后不再更新，而主机时间戳持续变化。真实数据和发布证据只保存在项目外层的私有部署记录中。

## 发布与回退

本次仅替换资源监控 Python 模块和 dashboard 静态资源，并重启 dashboard 用户服务。聊天、Agent 和模型进程保持运行。发布目录保存原模块、原 SHA256、旧前端目标、`rollback.json` 和部署前后的服务 PID。启用失败时自动恢复旧模块和前端链接；手动回退前必须确认当前模块 SHA256 和前端链接仍属于该发布批次，再按清单恢复并只重启 dashboard 服务，避免覆盖后续版本。
