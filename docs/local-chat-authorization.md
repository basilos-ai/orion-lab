# 本地聊天授权与 403 排查

本地 React 页面通过 Vite 代理访问设备聊天服务。GET `/api/session` 的权限由后端读取的 `trusted_client_ips` 和实际 TCP 来源 IP 决定；后端不会因页面运行在 localhost 就自动信任另一台电脑，也不使用客户端传来的 X-Forwarded-For 授权。

## 临时停用来源 IP 白名单

后端私有 settings.json 支持 `trusted_client_ips_enabled`。缺省或设置为 `true` 时继续检查白名单；只有明确的 JSON 布尔值 `false` 才关闭来源 IP 限制，字符串 `"false"`、数字 `0` 和 null 均不会关闭它。此开关不放入 Vite 变量或公开设备配置。

```json
{"trusted_client_ips_enabled": false}
```

关闭后，能够访问聊天服务的客户端可正常建立设备会话，不再要求 IP 预先登记。原 `trusted_client_ips` 列表保留；恢复为 `true` 或移除开关即可重新启用。开关变更需确认没有活动任务，再重启聊天桥接加载。

停用 IP 白名单后，12 小时 HttpOnly 会话、会话与连接来源绑定、同源检查、内部服务令牌、设备身份、输入审核、模型范围及项目审批继续生效。没有有效会话的写请求仍返回 401，跨站请求仍返回 403。它不会增加账户登录机制。

## 区分三类错误

| 请求 / 结果 | 含义 | 处理 |
| --- | --- | --- |
| GET /api/session 返回 403、authorized=false | 设备不信任当前请求的来源 IP | 管理员核对当前电脑实际访问设备的 IP，与私有白名单比较 |
| POST 返回 401、session_required | 会话 Cookie 缺失、过期或在聊天桥接重启后失效 | 刷新页面重新建立正常设备会话 |
| POST 返回 403、不接受跨站请求 | Origin / Host 不一致，或被判定跨站 | 检查页面地址和代理，不放宽后端同源校验 |

设备健康接口可访问不等于聊天已授权。`/api/session` 成功后，页面应显示“设备已连接”；正常输入且模型就绪时允许发送。会话 Cookie 保持 HttpOnly、SameSite=Strict 和 12 小时有效期，设备身份 Cookie 单独保留，不通过清理身份来修复授权问题。

## 按既有机制处理

1. 确认设备身份，复用已验证的 SSH 主机记录与现有管理员身份。主机地址变化时，使用事先核实的主机别名；不关闭主机密钥校验。
2. 读取当前电脑实际到设备的来源 IP。多网卡、VPN、DHCP 变化都可能使它不同于旧记录；以实际连接为准。
3. 在设备私有目录备份 settings.json，备份权限设为 0600。只在 `trusted_client_ips` 中追加已核实的当前 IP，保留原条目和其他配置，原子保存。不加入网段、通配符或前端可读配置。
4. 确认没有聊天、Agent 任务、模型切换或正式评测正在运行。该配置在服务启动时加载，因此需按既有运维方法重启 `o6n-smart-chat.service`；这不是发布前端或后端代码。
5. 刷新本地页面，验证 `/api/session` 返回 200、authorized=true，Cookie 正常下发，Origin 与 Host 仍匹配。现有 Vite 代理使用 `changeOrigin: false`，不要为消除 403 盲目修改它。
6. 首次真实验收选择“仅本地”及已经就绪的回答模型，使用不含敏感内容的短问题，核验流式、真实上游模型、上下文和刷新恢复。不得把模型选项的 ready 标记当作实际调用成功。
7. 再验证未登录 POST 仍返回 401、跨站 POST 仍返回 403。设备白名单、会话绑定、输入审核和项目审批边界继续生效。

私有配置、Cookie 值、服务令牌、完整模型回执与真实对话截图不进入源码。具体设备的操作记录放在项目外层排障资料中，本地运行证据放在被忽略的 `.runtime/` 下。DHCP 地址再次改变时，按同一流程处理；不要将白名单自动扩大为整个局域网。

撤销新增授权时，管理员对照私有备份，只移除本次新增 IP，保留后来发生的其他配置修改；确认空闲后重启聊天桥接。不要直接用旧配置覆盖后续变更。
